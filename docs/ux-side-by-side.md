## What matches today

- Submit → list → get → status pills (`queued` → `running` ⇄ `paused` → `succeeded` \| `failed` \| `canceled`). `paused` is non-terminal. Event trail filter-by-kind + JSON/JSONL salvage export are thinner (labeled **not** SIEM / **not** regulatory defensibility).
- Job detail for a selected run (identity, timestamps, current message/stage, stub vs runtime `backed`). Failed/canceled jobs surface a **terminal** summary (status + message + optional last events / stage) — labeled **not** SIEM / **not** iec audit product. Recoverability (thinner): handoff + payload export for operator/ctl re-admit (survives guest restart when history is persisted); cancel/fail does **not** auto-retry; no resume-from-failed. Progress prefers durable path-slice counters when a hook provides them, with a named timeline (`admit` / `project` / `fold` / `complete` or hook-provided) plus investigate ownership tags and completed vs current vs pending; otherwise stub “stage i of n” without fake names. Events prefer durable JSONL when a hook provides them; otherwise process-memory. Historical comparison (thinner) against recent same-catalog / same-kind-class jobs in guest history (in-process plus local lab files): elapsed for this run + priors; typical/ETA only from real succeeded prior walls. History persistence (thinner): `.sos/jobs` / `PANORAMIX_SOS_JOBS_DIR`; fail-closed if disabled; **not** a SIEM. Investigate (thinner): catalog name + short digest called out for cross-check; static path-slice ownership tags when hooked; event trail on the same panel.
- Cancel of a live run with clear framing and `canceled` (one L). Cancel is not pause. Durable cancel is **ctl-mediated**. Stub-backed cancel is **guest local**. When a durable hook is active (`PANORAMIX_CTL_HTTP` preferred or `PANORAMIX_RUNTIME_ROOT`), guest `POST .../cancel` signals runtime cancel first (same honesty as pause), then marks the guest job terminal — or follows hook `status()` when ctl already reports terminal. Job detail / list refresh prefers hook `status()` when `runtime_ref` exists so Temporal-backed runs show paused / running / terminal from ctl, not a stale stub clock. Terminal cancel is **409**. Fail-closed without hook (inert default unchanged). Cancel/fail does **not** auto-retry. Not guest→ctl HTTP over the mesh. Not #70 Done.
- Pause/Resume on the **durable path** (injected hook or opt-in lab adapter): guest `POST .../pause` → `paused`, `POST .../resume` → `running`, `pause_resume: true` on those responses. Stub-only jobs **409** `stub_only`; UI controls stay disabled with an explanation. Operator/ctl: `python3 -m runtime.apply reserve-temporal pause --id cw_…` and `python3 -m runtime.apply reserve-temporal resume --id cw_…` (or the same verbs on loopback ctl HTTP when `PANORAMIX_CTL_HTTP` is set). Operator UI badge (from `GET /v0/info` `jobs.durable_hook`) says the durable path is active **only** when the HTTP adapter is hooked — no pretend when stub. One-shot lab compose: [`docs/lab-compose.md`](lab-compose.md).
- Opaque WorkHandoff emit (`kind` / `class` / `payload_digest` + `id` / `status`) and payload export for the ctl path. Failed/canceled recoverability points at the same exports for operator/ctl `reserve-temporal admit --handoff JSON`. Guest does **not** call `runtime.apply compute-work`. Default guest does not invoke apply; opt-in lab may talk loopback ctl HTTP or subprocess `reserve-temporal` only.
